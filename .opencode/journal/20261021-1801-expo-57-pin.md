# Downgrade the Expo tooling to SDK 57

- Acceptance criteria:
  1. The mobile app runs on Expo SDK 57 (manifest + installed tree).
  2. `npx expo` resolves to the SDK 57 CLI from every directory in the repo,
     not to the registry's `latest` (SDK 58).
  3. `scripts/verify.sh all` is green and `npm audit --omit=dev` is read.
  4. Committed and pushed through the pre-push gate.

- Pre-mortem (most likely failure / evidence that catches it):
  *Failure:* adding `expo` to the ROOT package.json hoists or shadows the
  mobile app's own install, or the root `npm ci` in the commitlint CI job
  starts failing on a peer conflict.
  *Evidence:* `cd mobile && npx expo install --check` still reports
  "Dependencies are up to date"; `scripts/verify.sh all` green; CI green.

- Plan (files, order):
  1. `package.json` (root) — pin `expo` to the SDK 57 line in devDependencies
     so `npx expo` at the repo root resolves locally instead of downloading
     SDK 58 from the registry. Root `package-lock.json` regenerated to match.
  2. `scripts/verify.sh` — advisory `expo install --check` so a future
     dependency bump that walks off SDK 57 is reported by the gate.
  3. `.github/workflows/ci.yml` — same check in the mobile job, so the
     alignment is enforced remotely and not only locally.

- Checks run (command → result):
  - `node -p "require('./mobile/node_modules/expo/package.json').version"` → `57.0.30`
  - `cd mobile && npx expo install --check` → "Dependencies are up to date" (exit 0)
  - `cd mobile && npx expo --version` → `57.0.31` (SDK 57 line)
  - `npx expo --version` at repo root → `58.1.13` (fetched from the registry — the actual drift)
  - `npm view expo dist-tags` → `latest: 58.0.16`, `sdk-57: 57.0.30`
  - `npm ls -g --depth=0` → no global `expo`; the 58 came from npx fetching `latest`
  - `grep expo package-lock.json` → every `expo-*` package already on 57.x
  - `git ls-files mobile/ios` → 0 tracked files (generated native dir is gitignored)
  - scratch install of `expo@57.0.30` → 12s, 333 MB, 284 packages (acceptable)

- Escalations (trigger → observation that resolved it):
  - *Contradiction* ("downgrade to 57" vs. an app already on 57) → the app was
    already on 57; the only thing off 57 was the CLI npx fetches from the
    registry when run outside `mobile/`. Resolved by pinning the CLI at the root.
  - *Surprise* (`expo --version` → 58.1.13 while `npm ls -g` showed no global
    expo) → the bare `expo` binary does not exist on PATH; the 58 came from the
    `npx` fallback fetching the registry's `latest`. Resolved by re-testing
    `npx expo --version` from `mobile/`, the repo root, and `/tmp`.
  - *Confidence/cheap-fix* (the CLI reporting 57.0.31 while the `expo` package
    is 57.0.30) → `expo/bin/cli` is `require('@expo/cli')`; the CLI reports
    `@expo/cli`'s own patch version. Same SDK 57 line, not drift.
